# Spec-Check

**Did the AI actually build what you asked for?**

A fast, heuristic completeness checker: it parses your spec into features,
searches the codebase for distinctive evidence of each one, and tells you
what looks built and what is missing. One command, no API keys, no LLM.

```bash
$ spec-check --spec "login, signup, dashboard, tasks, dark mode" --dir ./my-app
```

## Why This Exists

Every developer using Copilot, Cursor, or Claude has this problem:
"I asked for 6 pages and it built 3." spec-check catches what's missing
before you do a manual file-by-file audit.

## What It Is (and Is Not)

spec-check is a **keyword/heuristic checker**, not semantic verification.
It looks for distinctive evidence of each feature — file names like
`login.tsx`, identifiers like `TaskList` or `reset_password`, compound
phrases like `dark-mode` — and weights identifier and filename hits over
plain text. It will not execute your code or judge whether a feature
*works*; it tells you whether there is any trace of it at all. That makes
it a cheap first gate: a MISSING result is a strong signal that the AI
skipped something.

To keep false positives down, common programming tokens (`export`,
`import`, `page`, `form`, `type`, `class`, `function`, `default`, ...)
are never used as search terms, and multi-word features must match a real
compound phrase (`task creation`, `TaskCreation`, `task_creation`), not a
lone word like "task".

## Usage

```bash
# Check from text spec
spec-check --spec "login page, signup page, dashboard, task list, dark mode" --dir ./my-app

# Check from spec file
spec-check --spec-file spec.md --dir ./my-app

# Auto-detect from README
spec-check --dir ./my-app --auto

# JSON output for CI/CD
spec-check --spec "..." --dir . --format json

# Strict mode (exit 1 if < 100%)
spec-check --spec "..." --dir . --strict
```

## How It Works

1. Parse your spec into individual features
2. Build distinctive search terms per feature: compound phrase variants
   (`task list` -> `TaskList`, `task_list`, `task-list`), a distinctive
   single token when there is only one (`csv export` -> `csv`), and a
   small curated synonym set (`login` -> `signin`, `auth`)
3. Search file names and file contents; hits in file names and inside
   identifiers score 2, plain-text hits score 1
4. Score each feature: FOUND (score >= 3), PARTIAL (1-2), MISSING (0)
5. Calculate completeness percentage

Heuristics have limits: unusual naming conventions can produce PARTIAL or
MISSING for code that exists, and boilerplate that mentions a feature can
produce PARTIAL for code that doesn't work. Treat the report as a fast
triage, not a proof.

## CI/CD Integration

```yaml
name: Spec Check
on: [push, pull_request]
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install git+https://github.com/Noumenon-ai/spec-check.git
      - run: spec-check --spec-file SPEC.md --dir . --strict
```
